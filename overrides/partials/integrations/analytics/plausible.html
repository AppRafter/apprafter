{#- Plausible, the same loader the landing runs (landing/web/src/components/layout/BaseLayout.astro). Kept byte-identical to it on purpose: two copies that drift are two properties reporting differently about one product. mkdocs-material's partials/integrations/analytics.html includes partials/integrations/analytics/.html, so `provider: plausible` in mkdocs.yml `extra.analytics` is what selects this file. `provider` is not a fixed enum — the theme ships google.html and resolves any other name through custom_dir, which is what makes this work with no plugin. navigation.instant swaps pages with history.pushState, and the loader handles that itself: it replaces `history.pushState`, listens for `popstate`, and sends a pageview whenever `location.pathname` changed. This file used to subscribe to material's own `location$` observable and send a second `plausible("pageview")` on top — written when the loader was assumed to capture full loads only. It does not: `autoCapturePageviews` defaults on, so every in-site navigation, and the initial load with it, was counted twice. A metric that is quietly 2x is worse than none, so the subscription is gone rather than the autocapture: one mechanism, and it is the one that dedupes repeat pathnames. The site is baked into the script, not passed here — the loader assigns `domain` last and overrides whatever `init()` is given. So which property these pageviews land in is decided entirely by which `pa-*.js` is requested below, and this one says `apprafter.dev`. -#}
